# Производительность

Hostlist применяется внутри `nfqws2`, после передачи пакета в userspace. Правила
WAN отправляют TCP 80/443, UDP 443 и выбранные ответные пакеты в NFQUEUE независимо
от домена. Исключённый сайт не обрабатывается стратегией, но платит за очередь.
Отключение Lua через `lua_cutoff` также не удаляет поток из NFQUEUE. В частности,
QUIC-видеопоток продолжает проходить через обработчик после handshake.

В версии 0.3.1 эта область перехвата сохранена. Ограничение QUIC только первыми
пакетами без доступного на прошивке `xt_connbytes` требует отдельной проверки:
непроверенное сокращение очереди может сломать обнаружение успешных соединений.
Не предполагается, что изменение установщика повысит скорость сети.

## Измерение

На компьютере, подключённом к G84 без VPN, выберите публичный тестовый файл:

```bash
python3 scripts/benchmark.py --url 'https://your-test-server.example/file.bin' --label active > active.json
```

Скрипт запрашивает пароль через OpenSSH, снимает `/proc/stat`, CPU процесса,
состояние очередей и счётчики Z2OUT до и после загрузки. Он не меняет сервисы,
firewall или настройки роутера. Загрузка ограничена 32 MiB и 20 секундами;
`--seconds` допускает 1–60 секунд. Сервер должен поддерживать Range.
HTTP-ошибки завершаются ненулевым `curl_exit`. `measurement_valid=false`
означает непригодный замер (например, получено меньше 1 MiB); скрипт возвращает
ошибку вместо успешного результата.

`--protocol http3` требует curl с поддержкой HTTP/3 и использует `--http3-only`:
результат не подменяется TCP при недоступном QUIC. Тестовый домен вне hostlist
показывает цену NFQUEUE без применения стратегий.

Для сравнения с обходом очереди на тестовой сети можно остановить сервисы
`/var/SaaS/zapret2/stop.sh`, повторить измерение с `--label bypass`, затем вернуть
их через `appmgrcmd add` с прежними аргументами и проверить `verify`.
Не выполняйте это на сети, где перерыв обхода блокировок неприемлем.

Выполните минимум три чередующихся замера каждого режима, на одном сервере,
в одно время и с одинаковым протоколом. Проверьте маршрут, отсутствие фоновой
нагрузки, рост счётчиков WAN и стабильность PID. Сравнивайте медиану скорости,
CPU и изменение drop-счётчиков очереди. CPU процесса приведён в процентах одного
ядра, общий CPU — всей системы. Короткие загрузки и разные CDN дают шумные числа.

Результат одного TCP-теста не описывает QUIC-видео, все сервисы или максимальную
скорость роутера. Аппаратный offload и сеть провайдера также влияют на результат.

## Первичный замер на G84 (0.3.1)

13 октября 2026 года выполнены по три последовательных TCP/HTTP/1.1 загрузки
10 MiB с `proof.ovh.net`, клиент подключён через G84. Для контрольного режима
watcher временно приостановлен, переходы NFQUEUE отключены; обработчик остался
работать. После измерения переходы восстановлены, watcher продолжил работу,
`verify` прошёл. Ниже медианы:

| Режим | Скорость, Мбит/с | Общий CPU, % | CPU nfqws2, % одного ядра |
|---|---:|---:|---:|
| Активные переходы NFQUEUE | 32,14 | 7,43 | 1,51 |
| Переходы временно отключены | 60,65 | 8,28 | 0,00 |

Скорость с активной очередью менялась от 9,87 до 63,79 Мбит/с; контроль —
60,64–62,84 Мбит/с. Drop-счётчики очереди не выросли. Такой разброс и
последовательный порядок измерений **не позволяют приписать разницу медиан
только NFQUEUE**. Замер показывает нагрузку процесса в этой сессии, но не
максимальную пропускную способность. Фоновый трафик и аппаратный offload не
отключались; весь видеопоток через userspace этим тестом не подтверждается.
QUIC в этом замере не тестировался. Для оценки устойчивой просадки нужны более
длинные, чередующиеся прогоны и отдельная серия HTTP/3.

## HTTP/3: реальные измерения

13 октября 2026 выполнены три последовательные загрузки `10Mb.dat` с
`proof.ovh.net` через рабочий G84 (версия на роутере 0.3.1). Клиент
`curl_cffi` использовал `v3only`; для каждого ответа подтверждены HTTP 200,
HTTP/3 и 10 485 760 полученных байт. Настройки роутера не менялись.

| Попытка | Скорость, Мбит/с | Занятость CPU роутера | Пакеты очереди, прирост | Drops |
|---|---:|---:|---:|---:|
| 1 | 8.01 | 6.25% | 556 | 0 |
| 2 | 8.25 | 6.11% | 638 | 0 |
| 3 | 7.80 | 5.48% | 718 | 0 |

Это замер активной конфигурации, **без контрольной серии с отключённой
обработкой**. Он не показывает процент потери скорости от zapret2: сервер,
Wi-Fi, offload и фоновые соединения не изолированы. Счётчик очереди относится
ко всему роутеру. Домен OVH отсутствует в списке обработки, однако эта серия
не позволяет отделить его пакеты в очереди от фонового трафика. Правила
перехвата допускают обработку исключённых доменов; её стоимость для одного
соединения здесь не измерена.
Возможное влияние аппаратного offload нельзя оценить по этой серии.

Для воспроизведения (только чтение состояния и загрузка тестового файла):

```bash
python -m pip install -r desktop/requirements.txt curl_cffi==0.13.0
python scripts/benchmark-quic.py --host 192.168.1.1 \
  --state-dir .build/benchmark-state --url https://proof.ovh.net/files/10Mb.dat
```

Клиент не допускает TCP fallback; значение HTTP/3 проверяется по
[документации curl_cffi](https://curl-cffi.readthedocs.io/en/v0.13.0/advanced.html).
Уменьшение перехвата видеопотока требует отдельного изменения правил с
проверкой сохранения работающих стратегий; в 0.4.0 такого ускорения не заявлено.
