# Архитектура порта для Innbox G84

## Ограничения штатной прошивки

Корень G84 — read-only SquashFS. `/etc` размещён в tmpfs и не переживает reboot.
Для установки используется небольшой постоянный раздел `/var/SaaS` (JFFS2).
Вместо systemd/procd прошивка применяет собственные `appmgrd`, `csmconf` и
`csmctl`.

## Поток пакетов

```text
LAN client
  -> mangle/POSTROUTING (WAN nas1)
  -> Z2OUT
  -> NFQUEUE 200
  -> nfqws2 + zapret Lua strategies
  -> ISP DPI
```

Ответные SYN/ACK и UDP/443 попадают в `Z2IN`. Созданные `nfqws2` пакеты имеют
маркер `0x40000000` и исключаются из повторного перехвата. `--queue-bypass`
сохраняет доступ в интернет, если обработчик очереди временно отсутствует.

Правила создаются одновременно в `iptables` и `ip6tables`. Они ограничены
WAN-интерфейсом `nas1`; локальный трафик домашней сети не затрагивается.

## Жизненный цикл

`appmgrd` запускает:

1. `/var/SaaS/zapret2/run.sh start` — правила и `nfqws2`;
2. `/var/SaaS/zapret2/watch-rules.sh start` — восстановление правил каждые 15 с.

`add-rules.sh` использует каталог `/var/tmp/zapret2-rules.lock` как совместимую
с древним BusyBox межпроцессную блокировку. В lock хранится PID владельца;
осиротевшая блокировка удаляется после проверки `kill -0`. `del-rules.sh`
удаляет все экземпляры переходов, поэтому корректно очищает и старую установку,
где могли появиться дубли.

PID-файлы `nfqws2` и watcher проверяются через `/proc/PID/cmdline`. Глобальный
`killall nfqws2` не используется: остановка воздействует только на процессы из
этой установки.

## Установка

Host-side installer проверяет SHA-256 payload и его версию до SSH-изменений,
определяет WAN по default route, выполняет обратимый тест IPv4/IPv6 NFQUEUE и
выбирает свободные либо уже принадлежащие проекту слоты `appmgr`. Payload сначала
распаковывается в `/var/tmp`, запускается с `--version` и лишь затем переключает
постоянный каталог. Предыдущая версия временно хранится как `zapret2.old`.

При обычной установке после `reboot` CLI ждёт исчезновения и возвращения SSH и
запускает `verify`. `--no-reboot` выполняет проверку текущего запуска, но не
утверждает, что persistence уже проверена.

## Проверенный сценарий

Итоговый пакет прошёл на физическом G84:

1. установку поверх существующей версии;
2. полное удаление с проверкой отсутствия каталога, процессов, правил и записей;
3. чистую установку;
4. проверку единственности каждого правила IPv4/IPv6;
5. reboot;
6. проверку процессов, `appmgrd`, правил и HTTP-доступности сервисов.
