# Восстановление

## Неудачная или прерванная установка

До остановки старой версии создаются новый каталог и приватный журнал
`/var/SaaS/zapret2.transaction`. Он хранит прежние значения принадлежащих проекту
слотов appmgr и состояние процессов. Каждый изменённый ключ читается обратно.

При ошибке установщик возвращает ненулевой код. Автоматический откат возвращает
старый каталог, настройки appmgr и ранее работающие сервисы. Staging и журнал
сохраняются для диагностики. Код 52 и сообщение `ROLLBACK FAILED` означают, что
откат не завершён: не удаляйте `.old`, `.failed` и `.transaction`.

После устранения причины, при работающем SSH:

```bash
./g84-zapret2.sh recover
```

Команда использует сохранённый на роутере скрипт восстановления, сохраняет журнал
в приватную локальную папку `backups/` и только затем очищает временные каталоги.
Повторный запуск скрипта отката безопасен до удаления журнала.

Если ошибка возникла ещё до полного снимка настроек, сервисы не изменялись.
Проверьте причину ошибки и резервные копии перед очисткой `.new`, `.transaction`
и `/var/tmp/zapret2-install`. Не удаляйте каталог `zapret2`.

## SSH работает, интернет пропал

```sh
/var/SaaS/zapret2/stop.sh
```

`--queue-bypass` пропускает пакеты при отсутствии обработчика очереди.
Проверьте состояние и `/var/tmp/zapret2.log`. Для запуска с обычными настройками:

```sh
appmgrcmd add zapret2 /var/SaaS/zapret2/run.sh start 1
appmgrcmd add zapret2-rules /var/SaaS/zapret2/watch-rules.sh start 1
/var/SaaS/zapret2/verify.sh
```

На этой прошивке `appmgrcmd` может вернуть ошибку после успешного IPC-запроса:
результат запуска проверяется по процессам, очереди и правилам. Если IPC не
запускает процесс, установщик выполняет прямой запуск принадлежащего проекту
скрипта. Регистрация сохранена, но управление через appmgr и автозапуск
подтверждаются только после перезагрузки.

## Проверка и правила

`verify` проверяет файлы, оба процесса и принадлежность PID, владельца NFQUEUE,
все рабочие правила и единственность переходов IPv4/IPv6. Доступность приложений
и автозапуск после reboot проверяются отдельно.

```sh
/var/SaaS/zapret2/status.sh
/var/SaaS/zapret2/add-rules.sh
```

Файл `/var/tmp/zapret2-rules.flock` не удаляйте: блокировка принадлежит открытой
дескрипторной записи ядра. Удаление файла может создать второй независимый lock.
После завершения или аварии владельца блокировка освобождается автоматически.

## Удаление

```bash
./g84-zapret2.sh uninstall
```

Перед удалением создаётся приватная резервная копия. Удаляются только слоты с
именами проекта; ошибка остановки, удаления регистрации или сохранения настроек
прерывает удаление файлов. Чужие каталоги `/var/SaaS` не затрагиваются.

При удалении только код 1 проверки наличия каталога считается подтверждённым
отсутствием. Ошибка SSH, чтения файла слотов, имени/пути appmgr, удаления слота,
контрольного чтения или `savecfg` возвращает ошибку. Оба слота проверяются до
остановки сервисов; чужой слот или некорректная карта слотов прерывает операцию.
При частичной ошибке удаления регистрация может быть изменена, но файлы
сохраняются; устраните причину и повторите удаление, используя резервную копию
при необходимости.
