# Проверки проекта

`./scripts/check-project.sh` запускает проверку синтаксиса, ShellCheck для
установщика и всех `router/*.sh`, сборку ustar-пакета, сверку хешей, тесты
отказов и Lua-тесты. Требуются Bash, Python 3, C-компилятор, ShellCheck,
ripgrep и LuaJIT. GitHub Actions также запускает MIPS-бинарник блокировки в QEMU
и проверяет, что пересборка не меняет опубликованные артефакты.

## Что воспроизводят тесты

`tests/test_failures.py` выполняет производственные shell-скрипты в отдельном
временном каталоге. `csmconf`, `appmgrcmd`, firewall и `/proc` заменены моделью
прошивки; реальные процессы роутера и сетевые правила компьютера не затрагиваются.

- Отсутствующий бинарник, процессы, неверный владелец очереди, каждое недостающее
  правило/переход IPv4 и IPv6, дубли переходов: `verify` обязан завершиться ошибкой.
- Ошибки копирования, прав, обоих переименований, частичной регистрации,
  сохранения конфигурации, запуска и итоговой проверки: установка обязана вернуть
  ошибку и восстановить предыдущие файлы, настройки и состояние сервисов.
- Ошибка самого отката явно возвращает код 52 и сохраняет журнал для `recover`.
  Повторный откат не удаляет уже восстановленную установку.
- Остановленные ранее сервисы не запускаются при откате; неоднозначный снимок
  настроек останавливает установку до изменений.
- Конкурирующие владельцы блокировки не входят одновременно в критическую секцию;
  после SIGKILL ядро освобождает блокировку без удаления файла.
- Режим `run.sh check` использует `--intercept=0`, не меняет firewall и не пропускает
  проверку из-за уже работающего обработчика.

`tests/test-lua.lua` загружает настоящий upstream `zapret-auto.lua` и проектный
адаптер. Нативные функции движка заменены заглушками. Проверяются ACK/FIN,
переполнение sequence number, отключение Lua после успешного соединения,
переключение стратегии, учёт одного отказа на соединение, сброс счётчика после
успеха и независимость доменов, клиентов и семейств IP.

## Границы проверки

Имитация и QEMU не подтверждают совместимость с прошивкой, доступность сайтов,
пропускную способность или загрузку после reboot. Это отдельные проверки на G84.
Не запускайте сценарии искусственного отказа на домашнем роутере.
`verify` проверяет структуру работающего сервиса, а не доступность приложений.

На G84 дополнительно проверяются права нового каталога после сброса UID движком
и запуск при недоступном IPC appmgr. В этом случае сервис стартует напрямую с
проверкой PID; сохранённая регистрация автозапуска проверяется после reboot.
