# Адаптивные стратегии в 0.3.0

`run.sh` загружает неизменённый upstream `zapret-auto.lua` версии 1.0.4 и
адаптацию `g84-auto.lua`. Upstream `circular` переключает наборы Lua-инстансов,
помеченных `strategy=N`, когда две неудачи происходят в течение 120 секунд.
Успешное соединение сбрасывает счётчик неудач. Это реакция на наблюдаемый трафик,
а не фоновое измерение скорости и не гарантия доступности всех сайтов.

## Область обработки

`hosts.txt` содержит домены YouTube, Instagram и других указанных сервисов.
Их поддомены включаются автоматически. `hosts-exclude.txt` имеет приоритет и
исключает `tbank.ru`, `tinkoff.ru`, `tinkoffbank.ru`, `mos.ru` вместе с поддоменами.
Соединения без распознанного имени хоста проходят без десинхронизации. Для
других сервисов добавляйте их домены и домены видеосерверов в `hosts.txt`.

Выбор хранится в памяти процесса отдельно для профиля, полного имени хоста,
семейства IP и адреса клиента. При перезапуске nfqws2 он сбрасывается. Такой ключ
не позволяет успешным запросам телефона обнулить сбои телевизора. Смена
временного IPv6-адреса клиента начинает новый подбор.

## TCP

Первым применяется `multidisorder:pos=1,midsld:seqovl=568`. Запасные наборы
используют другую длину перекрытия и сочетание fake с multidisorder. Они
переключаются по повторам TCP и ранним сбросам/закрытиям TLS.

В штатном ядре проверенного G84 нет `xt_connbytes`. Поэтому входящие TCP-пакеты
перехватываются только с SYN/ACK, RST или FIN; весь входящий видеопоток в очередь
не отправляется. `g84_success_detector` определяет успешную передачу по ACK
клиента, подтвердившему более 4096 байт от сервера. Вычитание ISN выполняется
32-битной функцией `u32add`, включая переход через ноль. После успеха обработка
Lua данного соединения отключается.

Ранний FIN при TLS и относительном sequence не более 256 считается неудачей:
сервер мог отправить короткий TLS alert вместо RST. Нормальные короткие HTTP
ответы под этот критерий не подпадают. Детекторы работают по признакам TCP,
не расшифровывают HTTPS и могут ошибаться при сетевых сбоях.

OOB не включён в поздний подбор по SNI: эта техника требует изменения handshake
с самого SYN и не совместима с подключением после получения имени хоста.

## QUIC

Первый набор сохраняет fake QUIC Initial с шестью повторами. Запасные наборы
используют два повтора или auto TTL. Неудача — шесть исходящих пакетов без
входящего ответа; первый ответ считается успехом. Другие UDP-протоколы не
подменяются. Сам QUIC-видеопоток продолжает попадать в NFQUEUE, как и в прежнем
профиле; отключение Lua после handshake не отменяет правила ядра.

## Диагностика

На роутере:

```sh
/var/SaaS/zapret2/status.sh
```

В `config` можно временно поставить `DEBUG_LOG=1`, затем перезапустить только
`zapret2` через `appmgrcmd`. Журнал появится в `/var/tmp/zapret2-debug.log`.
Ищите `circular: rotate strategy`, `g84: server data acknowledged` и
`automate: host record key`. Журнал содержит адреса и домены, поэтому не
публикуйте его целиком. После проверки верните `DEBUG_LOG=0`, перезапустите
процесс и удалите журнал, чтобы не расходовать RAM и процессор.

Скрипты используют `/bin/ash`: в этой прошивке `/bin/sh` — другой BusyBox shell,
не поддерживающий функции обвязки. `command -v` отсутствует даже в штатном ash,
поэтому доступность ip6tables проверяется вызовом `ip6tables --version`.

На G84 Lua-проверки можно запустить после загрузки `scripts/test-g84-auto.lua`
в `/var/tmp`:

```sh
BASE=/var/SaaS/zapret2
"$BASE/nfqws2" --intercept=0 \
  --lua-init=@"$BASE/zapret-lib.lua" \
  --lua-init=@"$BASE/zapret-antidpi.lua" \
  --lua-init=@"$BASE/zapret-auto.lua" \
  --lua-init=@"$BASE/g84-auto.lua" \
  --lua-init=@/var/tmp/test-g84-auto.lua
```

Тест проверяет ACK, переполнение sequence, направления и адреса клиентов,
ранний TLS FIN и отключение Lua. `--intercept=0` не подключается к рабочей очереди.

## Границы проверки

Проверка главной страницы не подтверждает воспроизведение видео, работу QUIC,
каждого приложения или телевизора. При тестировании через SSH SOCKS трафик
исходит от роутера; дополнительно проверяйте обычные LAN-клиенты без VPN.
Если TLS доходит до проверки сертификата, отдельно проверяйте доверие к CA
на клиенте. Роутер не устанавливает сертификаты на пользовательские устройства.
